ML Trauma Assessment

A computer-vision prototype that classifies an uploaded injury photograph — abrasion, bruise, burn, laceration, or normal skin — combines that finding with patient vitals and GCS to produce a prototype risk estimate, and surfaces protocol-based considerations for the predicted injury type.

Launch ML Trauma Assessment → Launch ML Trauma Assessment Code → Read the full technical reports →
Educational / research prototype — not for clinical decision-making. Injury classification and risk estimates are outputs of a small demonstration model trained on limited data. They are not a diagnosis and must never replace a hands-on assessment, protocols, or medical direction.
How to use it

Manual

1

Enter patient context

Fill in age, pain score (0–10), and vitals — heart rate, systolic/diastolic BP, SpO2, respiratory rate, and GCS — in the sidebar.

2

Upload an injury photograph

Upload a photo of the injury. The image displays for confirmation before you run the assessment.

3

Run the AI assessment

The computer-vision model classifies the injury into one of five categories (abrasion, bruise, burn, laceration, normal skin) and returns a confidence score and the full probability breakdown across all classes.

4

Review the prototype risk estimate

Combining the image classification with the vitals and GCS you entered, the system returns an apparent-risk band (low / moderate / high) with the findings that drove it — for example, a low GCS or a high pain score alongside the classified injury.

5

Check protocol-based considerations

Based on the predicted injury type, the tool surfaces relevant protocol-based considerations — for a laceration, that includes assessing the wound and mechanism of injury, severity, external hemorrhage, and distal circulation, sensation, and motor function.

1. Project Title

Development of an Artificial Intelligence Machine Learning EMS Injury Assessment Prototype Combining Computer Vision, Machine Learning, and Protocol-Based Information

2. Project Overview

The AI EMS Assessment system was developed as an experimental software prototype designed to demonstrate how artificial intelligence could combine image classification and patient information within a single EMS-oriented interface.

The system combines three primary components:

  • Computer vision for classification of injury photographs.
  • Machine learning for a prototype risk estimate based on patient information and vital signs.
  • Protocol-based information associated with the predicted injury category.

The system was implemented using Python and Streamlit. The computer-vision component uses a ResNet-18 neural network architecture through the timm library. The risk component uses a previously trained machine-learning model loaded through joblib.

The prototype was developed for educational and research purposes and was not designed or validated as an autonomous clinical decision-making system.

3. Development Objective

The primary development objective was to create a functional prototype capable of accepting two forms of information:

Patient information
  • Age
  • Pain score
  • Heart rate
  • Systolic blood pressure
  • Diastolic blood pressure
  • SpO₂
  • Respiratory rate
  • GCS
Visual information
  • Injury photograph

The system processes these inputs and produces an integrated output containing:

  • Predicted injury classification
  • Model confidence
  • Classification probabilities
  • Patient vital signs
  • Prototype risk estimate
  • Screening flags
  • Protocol-based considerations
  • Model limitations

10. Computer-Vision Model

The computer-vision component uses a ResNet-18 convolutional neural network architecture.

The model is created using the timm library.

The application does not use pretrained ImageNet weights during inference. Instead, it creates a ResNet-18 architecture with the number of output classes determined by the classes stored in the trained checkpoint.

The trained model parameters are loaded from:

injury_model.pth

The checkpoint contains:

model_state

classes

The model_state contains the learned neural-network parameters.

The classes value provides the injury categories recognized by the model.

11. Model Loading

The trained model is loaded using PyTorch.

The checkpoint is loaded with:

map_location="cpu"

This allows the prototype to run inference on a computer without requiring a dedicated GPU.

After loading the trained parameters, the model is placed into evaluation mode.

This ensures that the model operates as an inference model rather than performing training operations.

12. Prediction Process

When the user selects:

the uploaded image is transformed into the required tensor representation.

The tensor is then passed through the injury-classification model.

The neural network produces a vector of output values corresponding to the possible injury classes.

These raw outputs are converted into probabilities using the softmax function.

17. Findings Module

The findings module combines the image-classification result with the rule-based screening information.

The first finding reports the image classifier's prediction and confidence.

Additional findings are generated if the patient's input values meet any of the prototype screening thresholds.

If no additional thresholds are triggered, the application reports that no additional prototype screening flags were triggered.

This creates a simple summary of the information processed by the application.

19. Caching and Performance

The application uses Streamlit's resource caching mechanism:

This is applied to the model-loading functions.

The purpose is to prevent the trained models from being repeatedly loaded every time Streamlit reruns the application.

This improves application responsiveness and reduces unnecessary model-loading operations.

  • The computer-vision model was trained on a limited wound-image dataset.
  • Validation accuracy does not constitute clinical validation.
  • The risk model was trained using synthetic data.
  • Model confidence does not represent clinical certainty.
  • Protocol considerations must be checked against current local guidance.

These statements are included to distinguish software/model performance from clinical validation.

25. Scientific Development Summary

The AI EMS Assessment prototype was developed as a modular Python-based system combining computer vision, machine learning, rule-based screening, and protocol information.

A ResNet-18 convolutional neural network was used for injury-image classification. Uploaded images were converted to RGB format, resized to 224 × 224 pixels, converted to tensors, normalized, and processed by the trained network. Softmax probabilities were used to identify the highest-probability injury classification.

A separate machine-learning model processed patient characteristics and vital signs to generate a prototype risk estimate. A rule-based layer independently identified predefined screening thresholds. Finally, a protocol module associated the predicted injury category with informational protocol considerations.

The integrated system was implemented using Streamlit to provide an interactive interface for entering patient information, uploading images, and viewing model outputs.

In an initial evaluation using 100 injury images, the injury classifier correctly identified 94 images (94%). The highest-confidence prediction corresponded to the reference classification in 90 cases (90%).

These results provide an initial technical evaluation of the prototype. They do not establish clinical validity, clinical safety, or effectiveness. Further testing with larger, independent, and appropriately representative datasets would be required before drawing conclusions about real-world clinical performance.

1. Study Title

Scientific Evaluation of an Artificial Intelligence Computer-Vision Prototype for Injury Classification

2. Purpose of the Study

The purpose of this study is to evaluate the performance of an artificial intelligence (AI) computer-vision prototype designed to classify injuries from photographs.

The evaluation will measure:

  • How accurately the AI identifies injuries.
  • How frequently the model's highest-confidence prediction is correct.
  • What types of errors the model makes.
  • Whether model performance varies between injury categories.
  • Whether the model's confidence values appear consistent with prediction correctness.

The system is intended as an educational and research prototype. The study does not establish clinical validity, clinical safety, or suitability for diagnosis or treatment.

3. Research Question
Primary Research Question

How accurately can the AI EMS prototype classify injuries from standardized injury photographs?

Secondary Research Question

How reliably does the model's highest-confidence prediction correspond to the correct injury classification?

4. Hypotheses
Hypothesis 1

The AI injury-classification model will correctly classify a high proportion of images in the independent test dataset.

Hypothesis 2

The prediction assigned the highest confidence probability will frequently correspond to the correct injury classification.

Hypothesis 3

The model's performance will vary between injury categories because some injuries may have visually similar characteristics.

5. Experimental Design

The study uses a retrospective image-classification evaluation.

A total of 100 injury images will be evaluated by the AI model.

Each image will have an established reference classification. The reference classification will be treated as the comparison standard for evaluating the model's prediction.

The AI will analyze each image independently and generate:

  • Predicted injury category
  • Probability for each available injury category
  • Highest-confidence prediction
  • Confidence percentage

The AI prediction will then be compared with the reference classification.

16. Statistical Analysis

For the 100-image evaluation, the observed classification accuracy was:

94/100 = 94%

A 95% confidence interval can also be calculated for the observed proportion. Using a binomial proportion interval, the approximate 95% confidence interval is 87.5%–97.5%.

This interval describes statistical uncertainty associated with the 100-image sample. It does not mean that the model is guaranteed to achieve an accuracy within this range on future datasets.

The size and composition of the dataset should therefore be considered when interpreting the result.

18. Discussion

The evaluation demonstrated that the AI prototype correctly classified 94% of the images in the tested dataset.

This result indicates that the model was able to identify the reference injury classification for most images in this particular test set.

However, the six incorrect classifications demonstrate that the model does not classify every image correctly. Examination of these errors is therefore important for understanding the limitations of the system.

The highest-confidence prediction was correct in 90% of cases. Because this percentage was lower than the overall classification accuracy, the confidence values did not perfectly correspond with prediction correctness.

This finding is important because a confidence value generated by an AI model should not automatically be interpreted as clinical certainty.

The results also cannot establish that the model will achieve the same performance on other datasets. Model performance may change depending on image source, image quality, injury category, population, camera, lighting, and other factors.

19. Limitations

Several limitations should be considered.

Sample Size

Only 100 images were evaluated. A larger test dataset would provide a more precise estimate of model performance.

Dataset Representation

The performance of the model depends on whether the test images adequately represent the types of injuries and image conditions encountered in the intended application.

Ground-Truth Classification

The validity of the evaluation depends on the accuracy of the reference classifications.

Model Generalization

Performance on the test dataset does not necessarily predict performance on images from different sources.

Confidence

The model's confidence percentage does not necessarily represent the actual probability that the prediction is clinically correct.

Clinical Validation

This experiment evaluates an AI prototype. It does not constitute clinical validation, and the results should not be interpreted as demonstrating that the system is safe or appropriate for clinical diagnosis or treatment.

The evaluation of 100 injury photographs showed that the AI EMS prototype correctly classified 94% of the tested images. The model's highest-confidence prediction corresponded to the reference classification in 90% of cases.

Proposed Clinical Application of an Artificial Intelligence Machine Learning EMS Injury Assessment System Proposed clinical application
Abstract

Emergency medical services (EMS) personnel must rapidly assess patients, identify potentially significant injuries, and determine appropriate next steps in environments where time and information may be limited. Artificial intelligence (AI) has the potential to provide additional informational support during this process through computer vision and machine-learning technologies.

This project developed an AI EMS Assessment prototype combining computer vision, a machine-learning risk model, rule-based screening criteria, and protocol-based informational support. The computer-vision component analyzes uploaded injury photographs and generates an injury classification and probability distribution. The risk component processes patient characteristics and vital signs to generate a prototype risk estimate. The system then displays relevant screening findings and protocol-based considerations through an interactive interface.

In an evaluation of 100 injury images, the injury-classification model correctly classified 94 images, corresponding to an observed accuracy of 94%. The highest-confidence prediction corresponded to the reference classification in 90% of cases. These results provide preliminary evidence of technical performance within the evaluated dataset.

Clinically, a system of this type could potentially be used as an adjunctive decision-support and documentation tool, rather than as a replacement for EMS clinical assessment, medical direction, or established protocols. Potential applications include assisting with structured assessment, highlighting predefined abnormalities, organizing information, and providing informational support. Before clinical deployment, substantial additional validation would be required, including prospective clinical testing, external validation, safety evaluation, bias assessment, human-factors testing, cybersecurity and privacy assessment, regulatory review, and appropriate clinical oversight.

1. Background

Emergency medical services operate in environments that can be unpredictable, time-sensitive, and information-limited. EMS personnel may need to evaluate injuries while simultaneously collecting vital signs, obtaining a patient history, documenting findings, and determining appropriate care according to applicable protocols.

Computer vision is a branch of artificial intelligence that allows computers to process and classify visual information. In healthcare research, computer-vision systems have been investigated for applications involving medical images and other forms of visual information.

Machine-learning systems can also process structured variables such as age and vital signs. When combined with an appropriate user interface, these technologies could potentially provide EMS personnel with an additional source of structured information during an assessment.

The AI EMS Assessment prototype was developed to explore this concept. The system combines injury-image classification with patient information and predefined screening criteria in a single interface.

Importantly, the prototype is not intended to independently diagnose patients or determine treatment. Its proposed clinical role would be limited to providing additional information that a qualified healthcare professional could consider alongside direct patient assessment, established EMS protocols, and medical direction.

2. Problem Statement

A major challenge in emergency assessment is the rapid organization and interpretation of multiple sources of patient information.

For an injury patient, relevant information may include:

  • Visual characteristics of the injury
  • Vital signs
  • Level of consciousness
  • Pain severity
  • Patient age
  • Mechanism and history of injury
  • Changes in patient condition

A software system capable of organizing these inputs could potentially reduce the amount of information that must be manually consolidated during an assessment.

However, incorrect AI outputs could also introduce risk. Therefore, any potential clinical application must ensure that AI outputs remain subordinate to professional assessment and established clinical procedures.

When a threshold is reached, the system displays a screening flag.

In a potential clinical implementation, such flags could be used to draw attention to recorded values that warrant further assessment.

They should not independently determine patient disposition or treatment.

6. Protocol Integration

The prototype includes a protocol-information component that associates injury classifications with predefined considerations.

A future clinical implementation could potentially connect this component to an institution's current, approved protocols.

However, protocol content can vary between jurisdictions and organizations. Therefore, a clinical system should not assume that a single set of recommendations applies universally.

A production system would require:

  • Clearly identified protocol source
  • Version information
  • Effective dates
  • Controlled updates
  • Local medical-director approval where applicable
  • Mechanisms to prevent outdated protocol information from being presented as current

The AI system should not create or modify medical protocols autonomously.

7. Proposed Role of Healthcare Professionals

The proposed system would operate under a human-in-the-loop model.

Under this approach:

  • The EMS professional performs the initial patient assessment.
  • Relevant information is entered into the system.
  • The AI generates informational outputs.
  • The EMS professional reviews the outputs.
  • The professional compares the outputs with the patient's actual condition and applicable protocols.
  • Clinical decisions remain under appropriate professional authority.

This approach is important because an AI model can produce an incorrect classification even when its confidence is high.

Information organization

Patient information, image findings, and screening results could be presented in a standardized format.

Additional informational support

The system could provide another computational assessment of an injury photograph.

Consistency

A standardized interface could encourage consistent recording of selected patient variables.

Documentation support

Image classifications and structured patient information could potentially contribute to organized documentation.

Educational applications

The system could also be used in simulation and EMS education to demonstrate how AI-generated information could interact with patient assessment.

These potential benefits remain hypothetical until demonstrated through appropriate clinical research.

9. Risks and Clinical Limitations

Clinical implementation would introduce important risks.

Incorrect classification

The computer-vision model may incorrectly classify an injury.

In the current 100-image evaluation, six images were incorrectly classified.

False reassurance

A high model confidence could potentially cause a user to place excessive trust in an incorrect prediction.

Missing clinical context

A photograph cannot capture every clinically relevant characteristic of an injury or patient.

Dataset bias

If training and testing data do not adequately represent the intended population and injury types, performance may differ in real-world settings.

Model drift

Performance could change over time as injury patterns, imaging devices, patient populations, or operational environments change.

Protocol changes

Clinical guidance can change. A system containing outdated protocol information could potentially provide inappropriate information.

10. Privacy and Security

A clinical version of the system would need strong privacy and security protections.

Injury photographs can contain identifiable patient information. Therefore, a clinical implementation would need appropriate safeguards for:

  • Image storage
  • Patient identifiers
  • Data transmission
  • Access control
  • Authentication
  • Audit logs
  • Data retention
  • Data deletion
  • Encryption

The current prototype should not be assumed to meet clinical privacy or cybersecurity requirements.

11. Clinical Validation Requirements

The current 100-image evaluation is a technical evaluation and should not be considered clinical validation.

Before clinical deployment, additional studies would be needed.

These could include:

Retrospective validation

Evaluate the system using a large, independently collected dataset.

External validation

Evaluate the model using data from locations and sources not represented in model development.

Prospective evaluation

Evaluate system performance in a real-world or appropriately simulated clinical environment.

Human-factors evaluation

Determine whether users correctly understand and appropriately respond to the system's outputs.

Safety evaluation

Identify circumstances in which incorrect AI outputs could result in harmful decisions.

Bias and subgroup evaluation

Evaluate performance across relevant patient and injury subgroups.

Reliability testing

Determine whether system performance remains stable under different image qualities, devices, lighting conditions, and operational environments.

13. Discussion

The prototype demonstrates the technical feasibility of combining computer vision, structured patient data, machine learning, and protocol information within a single EMS-oriented application.

The 94% observed accuracy in the 100-image evaluation provides an initial measurement of computer-vision performance. However, the result should be interpreted within the specific conditions of the experiment.

The proposed clinical role of the system would therefore be fundamentally different from autonomous diagnosis. Rather than replacing professional assessment, a future validated version could potentially provide an additional layer of structured information.

The distinction between prediction and clinical diagnosis is critical. An AI model analyzes the information provided to it according to patterns learned during development. A healthcare professional evaluates the patient using information that may include physical examination, history, mechanism of injury, vital signs, clinical context, and other factors that may not be available to the AI system.

Consequently, an AI-generated classification should be treated as one source of information rather than as a definitive diagnosis.

14. Future Development

  • Developing a confusion matrix.

  • Improving protocol-version management.
  • Adding comprehensive audit logging.
  • Conducting human-factors research.
  • Conducting appropriate clinical validation studies.
  • Evaluating regulatory requirements before any clinical deployment.

16. Conclusion

The AI EMS Assessment prototype demonstrates a possible approach for integrating computer vision, machine learning, structured vital-sign information, and protocol-based information into an EMS-oriented software platform.

In the initial evaluation of 100 injury images, the injury classifier achieved an observed accuracy of 94%, while its highest-confidence prediction was correct in 90% of cases.

These results demonstrate preliminary technical performance but do not establish clinical effectiveness.

If further research demonstrates sufficient reliability, safety, generalizability, and usability, a system based on this concept could potentially be developed as an adjunctive tool for EMS assessment, documentation, education, and decision support.

Any future clinical implementation would require appropriate validation, clinical oversight, privacy protections, human-factors evaluation, regulatory consideration, and integration with current local EMS protocols.

The fundamental intended role of the technology should remain supportive rather than autonomous: AI may help organize and interpret information, while qualified healthcare professionals remain responsible for evaluating the patient and making clinical decisions.
